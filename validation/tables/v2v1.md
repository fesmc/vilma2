# VILMA2 against VILMA1 — the last deglaciation, ℓmax 170

Generated by `analysis/check_v2v1.jl`.

Both backends run behind the same driver on the same GLAC-1D forcing and the same output grid, referenced to the same file — VILMA2's own LGM reference state (`i_eq = 2`; the 26 ka load held 30 kyr) — with the degree-1 frame matched (`deg1_frame = "cm"`). The viscosity field is shared by construction: `experiments/make_vilma1_visc.jl` applies VILMA2's own clamp to the Bagge et al. (2021) file both backends read (`validation/data/input/bagge2021.nc`, lon-lat-r, not the FesmData product that is the model default), because VILMA1 reads its NetCDF directly through `io_nc3in` and none of the native clamping reaches it. `C_ocean` and `bsl` are VILMA2 diagnostics computed the same way for both backends and are therefore not independent between them.

**With an LGM datum there is no initialization asymmetry to caveat.** VILMA1 begins at its own reference with no first-step jump and VILMA2 begins at a held-load state of its own Earth model. Neither needs a spin-up. The `i_eq = 1` pairs, and the seven datum-hunting pairs that preceded them, are retired.

## Differences that are not solver error

* **Sub-steps within a coupling interval** — VILMA2 sub-steps adaptively to its own Maxwell stability limit; VILMA1 takes `vilma_v1_nsub` uniform sub-steps (12 here, an 8.33 yr step against a measured 11.0 yr Maxwell limit for this structure).
* **Radial discretisation** — the two codes integrate the same viscosity field onto their own element grids.
* **Degree-1 frame** — matched here (`cm` in both), and panel (c) of the summary figure is what keeps it checkable.
